# larkaxctl 命令参考

`larkaxctl` 是 larkax 的运维命令行。根帮助页（`larkaxctl --help`）只列一级命令与当下
要用的那几行；本文件写全局约定、退出码边界与各命令的完整说明。

一条命令的二级动作、参数与详情在它自己的帮助里：`larkaxctl <命令> --help`，
或 `larkaxctl help <命令>`。

## 全局约定

这几条对所有命令生效，写在子命令的前面或后面都认。

### 环境变量

运维命令只读下面这几个环境变量：

| 环境变量 | 用途 |
|---|---|
| `LARKAX_DB_DSN` | 数据库连接串 |
| `LARKAX_ENV` | 环境名 |
| `LARKAX_LOG_LEVEL` | 日志级别 |
| `LARKAX_MASTER_KEYS` | 主密钥。只有需要它的命令才读：`channel` 的写入、`secret rotate` |

`LARKAX_ROLE` 与运维命令无关。命令行自身的配置加载见 `internal/config` 的 `LoadOps`。

### `.env` 与 `--env-file`

`.env` 文件的取值规则：

- 不给 `--env-file` 时，从当前目录往上找，**不越过 git 仓库根**，用最近的那一份。
- `--env-file <路径>` 指定另一份文件。
- 两种来源都**只填补尚未设置的环境变量**：已经在环境里导出的变量优先，`.env`
  补不上它。所以一份注入的生产环境不会被误带的开发 `.env` 覆盖。

只用 `.env`、不在环境里导出任何变量也可以。

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 其他失败 |
| `2` | 命令行参数错（缺字段、取值解析不了、标志组合不对） |
| `3` | 连不上数据库 |
| `4` | 约束冲突（唯一键、外键、要改或要查的那一行不存在；同一幂等键已经对应另一笔入账） |

**`1` 与 `2` 的分界在「谁校验出来的」。** 命令行解析阶段就能判定的参数错归 `2`；
**写入路径自己校验出来的**参数问题——作用域与归属的组合、表达式编译不过、渠道
类型不认识——归 `1`。脚本按这两档分派时按这条线切。

上面这几个数是命令行的对外契约。按**触发条件**分的完整一张表（多出「体检结论」
那一档 D，它不打第二行、退出码照旧非零）见 [cli-output.md](cli-output.md) 的
「退出码」一节。

### 短选项

短选项固定为下面六个，其余选项一律写全名：

| 简写 | 全名 |
|---|---|
| `-u` | `--user` |
| `-m` | `--model` |
| `-o` | `--format` |
| `-v` | `--verbose` |
| `-q` | `--quiet` |
| `-V` | `--version` |

**`-V` 打版本号，`-v` 是详细模式。** 另外两条成对出现的约定：`-o` 与 `--format`
一样，写在子命令前后都认；`--verbose` 与 `--quiet` 不能同时给，两个一起给是参数错。

安全、财务与边界类的选项**不开短选项**，必须写全名：上游渠道、凭证来源、外部单据号、
速率上限、生效截止这几类。它们写短了容易看错也容易按错。

### 机器可读输出

`--format json` 把 stdout 收成一份 JSON，提示与警告走 stderr，给管道下游的 `jq`
与探针用。取值不合法时报参数错，不静默回落成表格。完整契约——状态符、上色条件、
表格对齐、时刻与时区——见 [cli-output.md](cli-output.md)。

## 按命令

每条一级命令的二级动作、参数与完整说明在它自己的帮助里（`larkaxctl help <命令>`）。
下面按根帮助页的分组逐条列出。

### 核心与诊断 (Core & Diagnostics)

#### `doctor`

系统健康与链路连通性体检。`--verbose` 时每项多打一段检查范围与完整原文。

#### `settings`

运行期动态配置项管理（`settings` 表）。

#### `version`

打印版本号与编译元数据。

### 路由与模型配置 (Routing & Models)

#### `channel`

上游渠道管理（网关、凭证、关联模型）。写入路径需要主密钥。

#### `model`

规范模型目录（catalog 基础定义）。

#### `alias`

模型别名映射（上游模型名 ↔ 规范名）。

#### `price`

模型计价规则与日历管理。日历数据文件的格式与约束见
`larkaxctl price calendar --help`。

### 权限与财务 (Access & Ledger)

#### `user`

系统用户管理（创建用户）。

#### `apikey`

API Key 访问密钥与额度管理。

#### `wallet`

用户钱包账户与入账管理。

#### `ledger`

财务账本管理（余额查询、分录校验、对账）。

### 系统与数据维护 (Maintenance & Data)

#### `migrate`

数据库版本迁移。`create` 只写文件、不碰数据库，其余各条都要连库。

#### `partition`

数据库月度分区维护。

#### `secret`

安全凭证与主密钥维护，密钥轮换（`rotate`）需要主密钥。

#### `maintenance`

数据留存与过期清理。

#### `snapshot`

请求结构快照管理。

#### `plugin`

动态插件系统管理。

## 搬过家的命令

下面这几条命令搬过位置，旧路径**仍然可用**，各条命令的 `--help` 末尾也写着它们：

| 旧路径 | 新路径 |
|---|---|
| `reconcile` | `ledger reconcile` |
| `rotate` | `secret rotate` |
| `idempotency cleanup` | `maintenance idempotency` |
| `calendar import` | `price calendar import` |

旧路径不进根帮助页，根帮助页只列正式写法。
