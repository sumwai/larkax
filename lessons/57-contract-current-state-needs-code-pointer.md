# 57 · 契约里的一句「现状」，指不到一处代码就是假话

**编号** 57 · **日期** 2026-10-28 · **摘要**：文档、契约或注释里描述「某个函数现在会做 X」
的句子，如果指不到一行代码，它就是在说假话——而读它的人会照着它写实现，写出来的东西
静默不工作，所有用例照绿。

## 现象

一次跨领域的改动要新增一个字段，共享契约段里写了一句：

> 重放会重新解析原始请求体，新字段会自然带上。

这句话被下游领域照抄进了源码注释与报告。可实际 `grep` 一遍该字段在生产代码里的
**写入点**，结果为零：解析函数只读不写。也就是说那句话描述的行为根本不存在。

顺着它写出来的实现会静默不工作：字段恒为 `nil`，功能整体不生效；而「缺省走另一条
分支」是合法状态，于是所有用例照绿，没有任何东西红。

真实的顺序是：契约先写结论 → 后来才补上生产者 → 中间那段窗口里，文档在说假话。

## 原因

- 「它会带上」是**意图**的自然写法，与「它已经带上」在中文里几乎同形。
- 契约段的读者是**要照着写码的人**，他不会去 `grep` 验证——他认为契约就是结论。
- 这种错**不会让任何测试红**：字段 `nil` 是合法状态，功能不生效与功能没被调用在
  输出上长得一模一样。

## 判断

> 写「某函数 / 某路径现在会做 X」之前，指一行代码。指不到就改写成
> 「我们要做到的是 X（尚未实现）」——**把意图与现状分开写**，别让读者自己猜。

- 布置任务时同理：「已确认」「已核实」这类词，后面要能跟一个 `文件:行号`。
- 评审时逐句问：这句话描述的是**现在**还是**目标**？两者混在一段的，就是隐患。

## 预防

- 契约段里描述现状的句子，**行号跟着句子走**，不用「已确认」这种无出处的措辞。
- 接收方有一条反向义务：契约里的每一句都核一遍再往源码注释里抄——抄进注释等于把
  这句话的保质期延长到下一次有人读它。
- 「新字段会自然带上」这类句子有一个更硬的验法：`grep` 该字段的**写入点**。读点存在
  不代表写入点存在，两者数量对不上就说明生产者还没落地。

## 关联

  本条核对的是「代码现在做什么」。
- 第 33 条（夹具按想象造，真实形状不同）：照着描述写、没去核对当时的事实。
