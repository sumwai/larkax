# 8 · 配置结构体打印出来就是明文密钥

**编号** 8 · **日期** 2026-10-16 · **摘要**：Go 的默认打印按字段展开，打印即泄密；`String`、`GoString`、`LogValue` 三个入口要一起挡。

**现象**

`internal/config` 的 `Config` 装着数据库 DSN（内含口令）与主密钥。实测：

```
fmt.Println(cfg)          → DBDSN:postgres://user:<明文口令>@localhost:5432/larkax
fmt.Printf("%+v", cfg)    → 同上，且主密钥按字节逐个列出
slog.Any("config", cfg)   → 同上
```

**原因**

Go 的默认打印行为是**按字段原样展开**。也就是说「什么都不做」等于主动泄密。
而打印一个结构体是顺手就会做的事：排查问题时 `slog.Any`、单测失败时 `t.Log(cfg)`、
`fmt.Printf("%+v")`。每一次都可能把主密钥写进日志文件、CI 输出、错误上报。

这类泄露的危险在于它**不报错**。测试通过、服务正常，只是密钥悄悄到了不该到的地方，
而日志的留存期与传播范围远大于密钥本身。

**解决**

1. `Config` 实现 `String()`、`GoString()` 与 `LogValue()`，三个入口都要挡：
   `%+v` 走 `String`，`%#v` 走 `GoString`（不会退化成 `String`），
   `slog` 的 `Any` 值优先走 `LogValue`。
2. `MasterKey` 单独实现 `String()`/`GoString()`：它会跟着 `Config` 一起出现，默认展开是明文。
3. DSN 用 `RedactDSN` 抹掉口令，**保留主机与库名**——排查「连错环境」时靠它们定位，
   而口令进日志就是泄露。
4. 补测试固定这个行为：拿一组敏感串去 `Sprint`/`%#v`，断言输出里不含它们、
   但含角色等非敏感字段。没有测试的话，后来加一个字段就会重新打开这个口子。

**预防**

- **凡是持有密钥的结构体，都要问一遍「它被打印时会怎样」。** 默认答案通常是「泄露」。
- 挡住 `String` 不等于挡住了 `%#v` 和 `slog`，三个入口是分开的，别只实现一个。
- 派生值（长度、标识、键名清单）可以留在打印结果里，原始材料不可以。
