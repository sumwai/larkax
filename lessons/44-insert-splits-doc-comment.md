# 44 · 往已有文件里插新函数，会把上一个函数的文档注释切给新函数

**编号** 44 · **日期** 2026-10-18 · **摘要**：往一个已有函数的**文档注释**与它的 `func`
之间插进新函数，那段注释就归了新函数，而原来的函数一句注释都没有。
`gofmt` 过、`go vet` 过、用例全绿——**没有一道门看得见**。

**现象**

在 `internal/auth/limits_integration_test.go` 里补一条用例，落成的样子是：

```go
// TestUpdateKeyRejectsNonPositiveID 钉住 id 的检查在连库之前发生。
//
// 0 与负数在库里不可能有一行（id 是 bigserial），放它进查询只会得到一句
// 「找不到」——那句话对着一个不可能存在的 id 是误导。
// TestUpdateKeyKeepsTheRightOwner 钉住那条 UPDATE 的连接条件。   // ← 新用例的注释从这里开始
//
// 语句是 `UPDATE api_keys … FROM users …`，两表靠 `u.id = k.user_id` 连起来。
// ……
func TestUpdateKeyKeepsTheRightOwner(t *testing.T) {
```

行为全对、用例全绿。但 `go doc` 与编辑器悬浮提示里，`TestUpdateKeyKeepsTheRightOwner`
带着 `TestUpdateKeyRejectsNonPositiveID` 的说明，而后者那句「钉住 id 的检查在连库之前发生」
从此不见了——它在屏幕上还在，只是说给了另一个函数听。

**原因**

注释块与它说明的那个声明之间，编译器不认识任何关系：它只是一串紧挨着 `func` 的 `//`，
`func` 前多一段注释、注释后多一个函数，都合法。

而插入点很容易落在**注释块内部**。写新函数时的动作通常是「找到上一个函数，在它后面贴
自己这一段」，手上确认的是「上一个函数长什么样」，落点却是「上一个函数的注释块与它的
`func` 之间」——两者之间没有任何标记，也没有谁会在写的时候拦住。

三道门都照不到：`gofmt` 只管排版，`go vet` 不看注释归属，用例只验行为。评审若只看 diff
里新加的那一段，看到的也只是「一段注释 + 一个函数」。

**解决**

新函数连同它的文档注释，插在**两个函数之间**——也就是前一个函数的 `}` 之后，而不是
注释块与 `func` 之间。

落完扫一眼这条对应关系，比新写一段脚本划算：

> **以标识符开头的那一行文档注释，它的下一处声明是不是就是这个标识符？**

本例里 `// TestUpdateKeyRejectsNonPositiveID …` 的下一处声明应当是
`func TestUpdateKeyRejectsNonPositiveID(t *testing.T)`，而不是别的函数。

**预防**

插入前先认一眼插入点的上方属于谁：

- 上方紧挨着的是一个 `}` → 这是函数与函数之间的空处，往这里插；
- 上方紧挨着的是 `//` → 那是某个声明的文档注释，**它归下面那个声明**，别插在中间。

第 42 条（注释里写什么、写给谁，脚本只判得了其中一半）。
