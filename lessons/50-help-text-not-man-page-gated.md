# 50 · `--help` 不进手页：改了帮助文案，没有一道门看得见

**编号** 50 · **日期** 2026-10-25 · **摘要**：帮助文本有两份独立来源——`--help`
打的是 `cmd/larkaxctl` 里的常量，手页是由「命令注册表 + `docs/cli-reference.md`」
渲染的产物。**没有任何一道门比对这两份文本的内容**：`check-man-pages.sh` 判的是
后者与其来源，`usage_test.go` 只核常量自比、根页形状，以及长版末尾那条「去向」
指向的**节名**存在。于是帮助里一句具体的承诺写错了，四道判据全绿、CI 全绿。

**现象**

一处命令的长帮助在讲「渠道名重名时怎么办」，写的是「命中多条时报错并列出候选的
**id 与名字**」，而实现打出来的候选是 `id=… 类型=… 地址=…`。

同一句 `docs/cli-reference.md` 里写的是「id、类型与地址」——**文档对、实现对、
只有帮助那一行错**。改掉它之后所有门禁照常通过，改动前后各跑一次都是一样的绿：
这道分岔没有任何一道门会红。

这一句不是措辞问题：同一次按名字查出来的候选，名字**必然全都一样**（按名字查的
就是这个名字）。照着「候选里的名字」重敲一遍，得到的还是同一句错。帮助在这里给出的
是一个**照做之后仍然失败**的动作。

**原因**

- **手页不是从 `--help` 生成的。** `internal/manpage/manpage.go` 的包注释写明了
  两个来源：命令注册表与 `docs/cli-reference.md`。`cmd/larkaxctl/man_test.go` 读的
  也是这份 Markdown（`referenceDoc`），不是 `*Usage` 常量。
- **`scripts/check-man-pages.sh` 判的是「两份源文件 → `man/`」这条路**（脚本头
  「判据（四条）」）：产物与提交的那一份逐字节相同、文件集合相等、非空、汉字与拉丁
  字母之间没丢空格。帮助常量不在它的输入里，改错了也不会让产物变一个字节。
- **`usage_test.go` 看起来像在管这件事，其实只管指针。** 它的
  `TestHelpPointersTargetRealDocSections` 从长版末尾的「见 `docs/cli-reference.md`
  的「xxx」一节」里取出**节名**，核那一节在文档里存在——它证明的是指针不指向空气，
  不是指针两侧说的是同一件事。其余用例是常量自比：非空、一屏、两版互相指路、
  根页命令清单与注册表一致。
- 于是缺口的形状是：**同一件事被写进两份格式不同的文本，而门只锁其中一份。**
  想补一道机器判等的门，就会撞上格式不同（终端排版 vs Markdown 小节）——要么造出
  脆断言，要么只能做很窄的词表检查（词表在这里的取舍见第 42 条），收益不如逐句读一遍。

**评审时怎么做**

改任何 `usage` 常量或帮助文案时，**拿实际输出对一遍文档**：

```sh
larkaxctl <命令> --help      # 或 <命令> help
```

把它的正文与 `docs/cli-reference.md` 同一节**逐句**对一遍。改了实现而两边文档都
跟着改了，仍然要回头看帮助——上面那次正是「两边文档都对、只有帮助那条没动」。
反过来改了文档，也要回头看帮助。

重点看**具体承诺**，这类句子最容易一边改一边漏：

- 输出里有哪些列、什么次序；
- 报错时列什么、让人下一步做什么；
- 某个旗标的缺省值、某个动作碰不碰别的表。

**为什么不加门禁**

不是漏掉的活，是权衡后的选择。`--help` 与 `docs/cli-reference.md` 是两种排版，
判等的机器要么断言整段字符串（改一个标点就红，最后被 `-update` 刷平），要么只查
几个词（漏的恰好是「列 id 与名字」这种语序与名词的偏差）。这一条**靠评审执行**，
所以派评审任务时把它写进任务书。
