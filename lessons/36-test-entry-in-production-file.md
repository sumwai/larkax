# 36 · 给用例留的入口写在生产文件里，deadcode 判它没人调

**编号** 36 · **日期** 2026-10-18 · **摘要**：改造一组终端输出时，为了让用例「只喂一项
就拿到那一行的形状」，在生产文件里加了一个单行打印函数，注释里还写明它是给用例用的。
门禁红：

```
✗ cmd/larkaxctl/doctor.go|printDoctorLive
```

**现象**

一条分支把几个子命令的输出收进同一层（表格、配色、缩进），其中几项的输出**要连库
才跑得起来**（整份报告里绝大多数行来自数据库检查）。为了单独验「真打上游那一项」
的四条分支，加了一个只打那一行的入口：

```go
// 它单独留一个入口是给用例用的……
func printDoctorLive(w io.Writer, l doctorLive, verbose bool) {
	printDoctorLine(w, doctorLiveLine(l), verbose)
}
```

它写在 `doctor.go` 里（生产文件）——理由是「用例与生产打的是同一段代码」。
门禁在 `check-deadcode.sh` 那一格红了，rc=1。

**原因**

`scripts/check-deadcode.sh` 底下的分析**不看测试文件**：它对「从入口可达」的定义
就是生产调用链，测试调过不算调用点。所以一个只被 `_test.go` 调用的函数，在它眼里
与一个谁都没调的废函数**完全一样**。

这一条不是误报，也不是能把测试算进可达到集合就能解决的：测试文件天然有调用方
（测试自己就是调用方），把测试算进去，这道门就再也照不到「只在测试里活着」的
生产代码——而那恰好是它最该报出来的一类。

**解决**

不是加白名单（那要把 `scripts/deadcode-allowlist.txt` 与脚本里的 `MAX_ENTRIES`
一起改，为一条**本该没有的**调用关系开口子）。改法是让生产路径本身成为那个
「共同的一段」：

```go
// 生产：喂它的全部行
printDoctorLines(w, doctorLines(rep), verbose)

// 用例：喂它关心的那一行，走同一条打印路径
func printDoctorLive(w io.Writer, l doctorLive, verbose bool) {   // ← 搬进 doctor_test.go
	printDoctorLines(w, []doctorLine{doctorLiveLine(l)}, verbose)
}
```

把生产那份内联的打印抽成 `printDoctorLines`，生产喂它全部行、用例喂它一行，
**两边走同一条路径**；入口函数本身搬进 `doctor_test.go`。改完门禁 24/24。

**顺带一个改善**：用例从此打的是生产那份代码，而不是它的复制品。原来那个入口的
动机（「让用例打到同一条路径上」）本来就是对的，只是它对「谁算调用方」这件事理解
错了——**把入口放对位置，动机才兑现**。

**预防**

> 我要给测试加的这个入口，**生产会调它吗**？

不会的话，它属于 `_test.go`：

- 想让用例与生产共用一段逻辑 → 把**那段逻辑**抽成两者都调的函数，
  再把入口放进测试文件；
- 想给一个包内小工具加「用例专用包装」 → 同样放 `_test.go`；
- 只有在生产真的有一条调用路径时才留在生产文件里。

**已知的相邻边界**（判据不同，各有各的门，别在这儿找统一答案）：

- deadcode **只报函数与方法**，包级 `var` / `const` 不进清单；
- 结构体字段的生死三道门都照不到（见第 31 条）；
- 导出**方法**有没有调用点是另一道门（`scripts/check-deadmethods.sh`），
  它按名字判，与 deadcode 不共享白名单。

**相关**：第 31 条（结构体字段没有门）、第 16 条（「没跑成」与「通过」长得一样）。
