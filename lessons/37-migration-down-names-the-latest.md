# 37 · 用「退最近一次迁移」验回滚的用例，会被下一条迁移悄悄换掉对象

**编号** 37 · **日期** 2026-10-18 · **摘要**：一条用例要验「最近加的那条迁移回滚得干净」，
用 `goose.DownContext` 退**一步**当作「回滚最近一次」。等仓库里多出一条迁移，同一次
调用退的就不是它了——**用例照样能过**，而它验的已经是另一条迁移。

**现象**

`internal/channels` 的 `TestMigrateSoftDeleteRoundTrips` 验的是 `00024`（渠道软删）
那条迁移：跑 `up`、做点破坏、`down` 回来、看 schema 是否复原。它回滚的方式是

```go
if err := goose.DownContext(ctx, db, "."); err != nil {   // 退「一步」
```

一条新迁移（`00025`，能力列三态）加进来之后，这句话退的是 `00025`，而这个用例
断言的是 `00024` 留下的东西——它撤错了对象。改动这条迁移的 agent 在跑全量测试时
撞上了，改成 `goose.DownToContext(ctx, db, ".", 23)` 才对齐。

**原因**

`DownContext` 的语义是「退**最近一次**」，而用例要的是「回滚**这一条**」。
两者只在「这一条恰好是最新的」时相等，而那是一个**会随仓库变化而失效**的前提——
前提失效的那一刻，用例改验的是别人。

它比普通的「用例过期」更难发现：**没有报错也能过**。如果两条迁移的 `down` 恰好
都只是 `DROP TABLE`／`DROP COLUMN` 之类，删除后的 schema 状态一样，用例红不了；
只有真正去断言「`00024` 的列还在不在」时才会红，而那要看这条用例写得有多具体。

**解决**

把「哪一条」写成**显式的版本号**，而不是「最近那一条」：

```go
goose.DownToContext(ctx, db, ".", 23)   // 退到 23，也就是把 24 及以上都回滚
```

同类的判据：任何「验最近一次 X」的用例，都要问一句「下一次 X 到来时它验的还
是不是它」。**迁移只是最容易撞上的一种**——schema 版本、迁移编号、嵌入的清单、
「最后一个」开头的枚举项都是同一个形状（与第 35 条「用例里写死的当前最大值」是
一对：那条是数会变，这条是**对象**会变）。

**预防**

> 这条用例要验的是「哪一个」？它现在是怎么被**指认**的——按下标、按「最新」、
> 还是按名字/编号？

按「最新」指认的，都要有一条**不依赖自己是最后一条**的指认方式。加新迁移时要
主动回头看：仓库里有没有别的用例正在用「退最近一次」验回滚（本次全仓搜过一遍，
`goose.DownContext` 只有这一处，`cmd/larkaxctl migrate down` 是产品行为、不算）。

**相关**：第 35 条（用例里写死的「当前最大值」）、第 25 条（两条分支各自的 CI 都绿、
合起来不绿）。
