# 43 · 等价的判据是「没有输入能区分」，不是「我想不出用例」

**编号** 43 · **日期** 2026-10-18 · **摘要**：变异测试留下存活之后，每一条都要判「等价变异 /
真缺口 / 不可达分支」。写理由时最容易滑掉的一步：把**关于当前用例集**的陈述
（「没有用例造得出它」）当成**关于输入空间**的陈述（「没有输入分得出两版」）。
两句写出来几乎一样，结论差一整个缺口。

**现象**

一轮整包变异（`internal/ledger/store`）留下 8 条存活，标注里混进了三种说不通的理由：

1. **说成「只改措辞」**：`unfreezeSubject` 里回查预留那条 SELECT 后面的 `err != nil`
   被取反。理由写的是「它只改错误文本的措辞……没有任何判据读它」——不对，它改的是
   **走哪一支**：回查成功时（也就是「缺钱包行」这条正常路径）变异版会走进失败那一支，
   把「用户 1 的 CNY 预留（请求 X）」换成「回查预留记录失败: `<nil>`」，
   一句**假诊断**。判据不读它，可运维读它，而那条用例本来就在跑这条路。
2. **说成「没有任何输入造得出它来」**：`Reconcile` 尾部 `finishReconcileRun(ctx, report, nil)`
   的 `err != nil`。对**原版那一支**这话成立（那次 UPDATE 失败确实不是应用层输入），
   可变异版的差别在失败路径上——把错误吞掉、把这一轮当成功返回。挂一个
   `BEFORE UPDATE … RAISE EXCEPTION` 的触发器就造出来了，本包别的用例早就在动 schema。
3. **一条存活谁也没认领**：`sortWalletKeys` 比较器里的第二支（`keys[i].Asset < keys[j].Asset`）。
   相邻的第一支（`keys[i].UserID < keys[j].UserID`）有 `!=` 守卫，所以拿掉它不影响结果；
   标注照第一支的理由写了一眼，第二支**没有守卫**，理由得另说（两版只在两个键**完全相同**
   时取值不同，而那时交换的是同一个值）——但它干脆没写，读清单的人不知道谁认领了它。

**原因**

- **等价性是关于输入空间的陈述，「想不出用例」是关于当前用例集的陈述。** 判的人手上只有
  后者，写的时候顺手就把「我试过」写成「分不开」，两句话在中文里几乎同形。
- **同一段代码里的两支，判据可能不同。** 守卫（`if a != b`）让一支平凡等价，另一支
  要靠结构证明；两支长得像，照抄邻行是最省力的动作。
- **失败路径的存活最容易被放过**：失败了才走的那几行，平时没有用例经过，于是
  「没有输入」与「没有用例」看起来是一回事。
- **理由写在源码注释里**，而判据说「每一条都在**用例里**写一行说明」。清单是照着用例读的，
  写在源码里等于没人认领。

**解决**

判据一句话，写在任务书与评审清单里：

> **能说出一个输入让两版不同，就不是等价**——那就补一条能钉住它的用例。
> 说不出，理由要写成「**哪种**分不开」，并给出结构理由或穷举证据。

- 「哪种分不开」有三类，各自要能自证：**守卫使两侧永远不等**（如 `if a != b` 之后的
  `<` 与 `<=`）；**两版只在两个值完全相同时不同，而那时输出是同一个序列**
  （结构体的字段只有那两个，交换不改变值序列）；**容量提示**（`make(map, n)` 的 `n`，
  与切片不同：map 容不下只是多扩一次，不会 panic）。
- **穷举小输入空间**比争论便宜：比较器这类「字段少、类型小」的函数，把
  全部长度 0..6 的输入排一遍，两版输出不同的输入**个数**就是结论。
- **两支分开判**，一行一条，别共用一句话。
- **标注写在用例里**（那条用例的注释块），清单才好逐条对账。
- **防「一次判完就完了」**：改完再跑一次整包变异——存活数要么下降，要么每一条都有
  站得住的理由；两次结果不一致的地方，就是上一轮判错的地方。

**预防**

- 派分诊任务书时写死三条：**能说出可区分的输入就不是等价**；**同一比较器的两支分开判**；
  **标注写在用例里**。（#643、#659 两次分诊都靠这三条。）
- 评审时逐条问一句：**「加上什么输入会让两版不同？」** 答不上来的，看它有没有给出
  结构理由或穷举证据；两者都没有，就是还没判。
- 分诊完的终验是**再跑一次变异**，不是读一遍 diff。

**关联**

- 第 23 条（一个守卫没人钉住，等于它没被证明在工作）：同族的「看起来被覆盖了」。
- 第 36 条（给用例留的入口写在生产文件里）：标注与入口一样，**写在哪里**决定它会不会被读到。
