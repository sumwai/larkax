# 23 · 一个守卫没人钉住，等于它没被证明在工作

**编号** 23 · **日期** 2026-10-17 · **摘要**：自测全绿不等于守卫被钉住；要对自测本身做一轮变异，逐个把守卫改成永假条件。

**现象**

给「整包没人 import」那道门（`scripts/check-unimported.sh`）写自测，28 条断言全绿。
写完做了一轮变异——把脚本里每个守卫逐个改成一个永假的条件，看自测会不会挂：

```
变异[关掉剥前缀守卫]            → 通过 26，失败 2
变异[关掉可达集合为空的守卫]    → 通过 26，失败 3
变异[关掉 go list -m 多行守卫]  → 通过 26，失败 2
变异[关掉认不出守卫]            → 通过 25，失败 2
变异[关掉白名单格式守卫]        → 通过 27，失败 0   ← 存活
变异[关掉条目数上限]            → 通过 27，失败 2
变异[关掉白名单存在性检查]      → 通过 26，失败 2
```

七个变异里**有一个存活**：白名单自身不合格式时不再失败，而自测照样报「通过 27，失败 0」。

那条守卫的作用是「白名单坏掉时不能继续比」——关掉它之后，这一轮会拿半份清单去比，
而半份清单的输出与「全部命中」长得一样。它是这道门最该有的守卫之一，
却是唯一一个**没人钉住**的。

**原因**

不是那条守卫没用，是**钉它的那条用例分辨不出来**。原来那条用例（用例 14）的形状是：

```
白名单：internal/orphan | lib        ← 栏数不足，坏行；此外没有别的条目
仓库：  internal/orphan、internal/spare 都没人 import
```

坏行被跳过之后白名单是空的，而两个包都没人 import，于是**照样**报「新出现的」
→ 退出码 1。守卫开着是 1，关掉也是 1。

用例只断言了退出码与一条错误措辞，而那条措辞是**解析循环**打的，跟守卫无关——
所以断言全过，守卫却没被碰到。

这与[第 21 条](21-invariant-proves-nothing-about-tier.md)是同一族，但方向不同：那条讲的是「一个不变式在两种行为下都成立」，
这条讲的是**两条不同的路径给出同一个退出码**。两者的共同点是
**断言里的量与被测的那个东西不在同一个维度上**——退出码相同 ≠ 走的是同一条分支。

**解决**

补一条**形状相反**的用例（14b）：让坏行对应的包**是可达的**（它本来会是一条陈旧条目）。

```
白名单：internal/orphan | lib | 库构件，先有先测
        internal/spare  | lib            ← 坏行，而 spare 已经可达
仓库：  internal/orphan 没人 import；spare 可达
```

于是跳过坏行之后 `new` 与 `stale` **都是空的**——**不比就通过**，
而输出与真的「全部命中」一模一样：

| | 守卫开着 | 守卫关掉 |
|---|---|---|
| 用例 14 | 退出码 1 | 退出码 1（分辨不出） |
| 用例 14b | 退出码 1 | **退出码 0**（静默通过） |

两个值不一样，断言才分辨得出来。补上 14b 之后重跑同一组变异，
**七个全部被杀死**（逐个都让自测至少挂 1 条）。

**预防**

- **给检查脚本写自测时，自测本身也要做一轮变异**：把每个守卫逐个改成永假条件，
  看自测会不会挂。挂不了的那个守卫，此刻只是「写在脚本里」，
  不是「被证明在工作」。变异测试在这类脚本上比在业务代码上更便宜——
  桩件是假的、跑一次几秒，一轮七个变异不到一分钟。
- **一条断言钉的是「哪条分支」，不是「什么退出码」。** 写 `rc == 1` 之前先问：
  把这条判据去掉，还会不会有别的路径也给出 1？会的话这条断言分辨不出它。
- 这类用例的正确形状常常是**反的**。正例（坏行对应的包没人 import）走的是
  「顺便也对」的那条路；反例（坏行对应的包是可达的）才是唯一能落到守卫上的那一条。
  写不出来反例时，先别急着说这个守卫测过了。
- 这与[第 16 条](16-silent-check-failure.md)（「没跑成」与「跑成了」同形）是一体两面：那里要防**输出相同**，
  这里要防**退出码相同**。修法也一样——让两条路径的结果长得不一样，
  或者用正向证据把「走的是哪条路」写出来。
