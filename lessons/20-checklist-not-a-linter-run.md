# 20 · 按清单自查不能替代真的跑一遍 linter

**编号** 20 · **日期** 2026-10-17 · **摘要**：人写的清单列的是「我以为会挂的地方」，而 linter 跑的是配置里全部规则，两者差多少清单作者不知道。

**现象**

同一个原因挂了三次 CI：

| PR | 挂在哪 | 自查怎么说的 |
|---|---|---|
| #153 | `govet` 的 `shadow`，4 处 | 「`shadow` 与 `errcheck` 逐处手工看过」 |
| #162 | 同上，1 处 | 同上 |
| #169 | `nilnil`，1 处 | 「`shadow` 分析器离线跑过，全仓 0 条命中」 |

三次都不是没查——第三次甚至离线把 `shadow` 跑了一遍、确实是 0 条命中，
而 CI 挂在**另一个检查器**上。查过的那一条没问题，没查的那一条有问题。

**原因**

本机没装 `golangci-lint`（AGENTS.md 早就写了「本地要用 `go install` 一份」，
一直没做），于是自查只能靠**人写的清单**。清单列的是「我以为会挂的地方」，
而 linter 跑的是配置里全部规则——两者差多少，清单的作者不知道。

更麻烦的是这两件事在报告里长得一样：

- `gofmt` / `go vet` 本机能跑，它们干净是**证据**；
- `golangci-lint` 的干净是**推断**，而且推断的措辞往往写成「逐处看过，干净」。

这和[第 16 条](16-silent-check-failure.md)是同一个形状——「没跑成」与「跑成了」看起来一样。这一条多一层：
**「没跑」被写成了「跑过且干净」。** 读者不会去追问，因为那句话是肯定的语气。

**解决**

1. 本地 `go install` 一份与 CI 同版本的 `golangci-lint`，提交前跑一遍。
   **注意版本**：CI 里是 `install-mode: goinstall`、版本写在 workflow 里，
   本地装的版本要跟它对齐，否则会重演[第 7 条](07-redline-line-filter-bypass.md)（工具版本比 Go 旧）那一类问题。
2. 在装上之前，报告里**必须写「没跑 golangci-lint」**，而不是「lint 干净」。
   把「哪一道门没有本地证据」当成报告的一个字段来填，别让它藏在措辞里。
3. 只想临时补一个检查器时，可以离线用 `golang.org/x/tools` 里的分析器跑
   （`go vet -vettool=...`）——但那只覆盖你挑的那一个，不能因此改口说「lint 干净」。

**预防**

- **一条 lint 规则有没有生效，只有跑一遍才算数。** 尤其当配置里开着
  `govet: enable-all` 时，「标准 vet 干净」不代表「带全部检查器的 vet 干净」。
- 报告里区分三档：**跑过且干净** / **跑过但没跑全** / **没跑**。含糊其辞的
  「看起来没问题」不属于任何一档，不要写。
- `//nolint` 要用在「这条规则说的确实是误报」的地方，并紧跟一行说明理由——
  仓库里已有的两处（`internal/billing/expr/dsl.go`、`internal/plugin/sandbox/runtime.go`）
  都是这个形状。用它来让 CI 变绿而不写理由，等于把这一条教训再踩一遍。
