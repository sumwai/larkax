# 4 · 就绪检查在无检查项时返回 503

**编号** 4 · **日期** 2026-10-16 · **摘要**：「检查项都通过」被写成「存在检查项且都通过」，依赖列表为空时实例会被永久摘除。

**现象**

`/readyz` 在依赖列表为空时返回 `503`，`{"ready":false}`。代码是 `ready := len(checks) > 0`，
而主服务此时传的正是空列表。

**原因**

把「检查项都通过」写成了「存在检查项且都通过」。当时没有业务流量所以无害，
但语义上错了：没有需要依赖的东西就是已就绪。任何编排系统都会把这个实例永久摘除，
现场表现是「服务起来了但一直不接流量」。

**解决**

改为 `ready := true`，只有检查项真的失败才置 false，并补了一条测试固定这个行为。
注释里写明：想让实例在依赖可用前不接流量，就去注册对应的检查项，而不是靠空列表。

**预防**

空集合、零值、nil 是默认分支里最容易写反的地方。凡是「全部满足」的判定，
都要单独想一遍「集合为空」时应该是什么结果。
