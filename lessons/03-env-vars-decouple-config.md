# 3 · 环境变量过多会让数据与配置脱钩

**编号** 3 · **日期** 2026-10-16 · **摘要**：环境变量必须跟着数据一起走，所以只留「连库前必须拿到」的那几个，其余进数据库的 `settings` 表。

**现象**

初始版本定义了十四个环境变量：主机、端口、用户名、密码、库名、连接池大小、多个超时、Redis 各字段。写起来繁琐，更要紧的是它埋了一个看不见的雷。

**原因**

环境变量必须**跟着数据一起走**。备份恢复、换机器、切环境时，如果有一批变量没同步过去，
数据就不可用了——数据库连上了，但连的是错的；或者连上了却因为某个开关写错而拒绝服务。
这类错误往往在几周后才被发现，那时已经没人记得当初设过哪些变量。

**解决**

按「是否必须在连上数据库之前拿到」划分：

- **必须在连库前拿到** → 环境变量，且尽量收敛。数据库与 Redis 改用单个 DSN 承载地址与凭证，
  不拆成五个变量；超时之类的项直接写进代码常量。
- **其余全部** → 数据库的 `settings` 表。它与数据同生共死，恢复数据就带回了配置。

另外，主密钥从单把改为**多把并存**（`<标识>:<base64>` 列表）。密文用数据密钥加密，
数据密钥用每把主密钥各包一份存在库里，于是任何一把都能解开：
轮换时新旧并存即可，弄丢一把也不会让存量数据变成废纸。

**预防**

- 新增环境变量前先问「它是不是必须在连库前拿到」，不是就进 `settings` 表。
- 密钥类配置也不进 `settings`（那里明文落盘且进备份），走 `channels` 表的信封加密。
