# 49 · 报变异体数量不带列名、口径与变异器集合，同一个量会被当成另一个量

**编号** 49 · **日期** 2026-10-25 · **摘要**：变异测试的汇总表有四个计数列，表外
还压着两项条件——跑的是整包还是收窄后的文件、开了哪些变异器。单报一个数，读者
会对不上账：`killed` 被当成候选总数，整包的候选数与窄口径的 `killed` 被相减，
同一位置的两条变异体被数成一条，两个变异器集合下的数被并排比较。

**现象**

同一个包、同一份代码，讨论里出现过的四种读法：

- 把 `killed` 列的数读成「这个包的候选总数」；
- 拿整包口径的候选总数与窄口径的 `killed` 相减，得出一个不存在的缺口；
- 把同一个 `行:列` 上的两条变异体数成一条；
- 把默认变异器集合下的数与显式打开 `--invert-logical` 的数并排比较。

**原因**

- **列名说明在数哪一类结果。** `killed` 只是四个计数列之一；候选是它与存活、
  超时、`Not covered` 之和。
- **口径决定参与变异的文件集合。** 整包与 `LARKAX_MUTATION_SCOPE=narrow` 覆盖的
  文件不同，四个计数列都只覆盖各自那一批。
- **变异体按位置报，一个位置可以挂多条。** 比较符 `<` 会同时被
  `CONDITIONALS_BOUNDARY` 改成 `<=`、被 `CONDITIONALS_NEGATION` 改成 `>=`，
  所以数位置不等于数变异体。
- **变异器集合决定生成哪些变异体。** `INVERT_LOGICAL` 默认关闭，`a || b` 在默认
  集合下一条都不生成；换一个集合，分母跟着变。

**判据**

报任何一个变异体数量时，三样一起给：

1. **列名**：`killed` / 存活 / 超时 / `Not covered` 里的哪一列，照表头抄；
2. **口径**：整包，还是只变异改动涉及的生产文件；
3. **变异器集合**：是否打开了 `--invert-logical`，以及 gremlins 的版本。

缺任何一样，这个数就不能与另一个数相减或比较。写全的例子：

> 整包口径、gremlins v0.6.0、`--invert-logical` 已开：`internal/keyquota` 的
> `killed` 是 2，存活 0，`Not covered` 6。

**预防**

- 从汇总表抄数之前，先把脚本打的那行「这把尺子」一起抄下来。
- 读到「`killed` 是多少」时先问一句：四个计数列加起来是多少，那才是候选总数。
- 同族：[第 17 条](17-number-copied-without-conditions.md)（数字要连条件一起记）、
  [第 43 条](43-equivalence-claim-needs-distinguishing-input.md)（存活要逐条判）。
