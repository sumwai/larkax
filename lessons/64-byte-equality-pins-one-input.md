# 64 · 逐字节断言的用例，钉的是它自己喂进去的那个形状

**编号** 64 · **日期** 2026-10-28 · **摘要**：一条断言「响应与上游原文逐字节相同」的用例，
看上去把整条转发路径钉死了。它钉的只是**喂进去那一个形状**。同一个字段的另一个取值
走的是另一条分支，用例照样绿、覆盖率照样高，而把那个取值故意改错，**整包一条都不红**。

## 现象

直通（把上游字节原样转发给调用方）有一条用例，夹具是上游在 `message_delta` 里给
`"input_tokens": 42`，断言响应体与上游原文逐字节相同。四条直通用例全绿。

同一批工作里要保护的性质是「上游报 0 是真值，不能当成没报」（整段 prompt
命中缓存时 `input_tokens` 真的是 0）。有人据此写了「那个用例就是反证——42 是这么送出去的，
0 同理」。**「0 同理」是推的，不是它证过的。**

把错读真接注进去——在写字节的那一层，把值为 0 的 `input_tokens` 删掉（正是要防的那种读法）：

```
$ go test ./internal/api/ -run 'TestNativePassthroughForwardsDelta'
ok  	...	0.008s          ← 原有用例全绿

$ go test ./internal/api/            # 整包，不带新用例
ok  	...	0.930s          ← 整包也全绿
```

候选答案「跑更宽的 pattern 就抓到了」也是错的：**整包运行都不红**。

补一条夹具为 `input_tokens: 0`（外加 `cache_read_input_tokens: 31`，即整段命中缓存的
真实形状）的逐字节用例之后，同一个变异：

```
--- FAIL: TestNativePassthroughForwardsZeroDeltaInputTokens
    native_stream_test.go: input_tokens 的 0 没到调用方（真值 0 被当成没报？）
FAIL	EXIT=1
```

失败文案里不带行号是有意的：那条用例在引入它的分支上才有，行号会随着后续编辑漂，
而这里要读者认的是**那句话本身**，不是它此刻在第几行。

## 原因

- **逐字节断言的有效域是输入，不是断言写法。** 「相等」这个词看上去是全域的（任何
  输入下都该相等），但一条用例只跑一个输入。同一个字段的不同取值在实现里常常落在
  不同分支上：42 走「有值就写」，0 走「0 是真值还是缺省」这一判。
- **正数样本尤其会掩盖零值分支。** 计数、金额、余额、限量这一类字段，正常样本总给正数，
  而实现里专门为 0 写的那条判断只在 0 时才执行。这和[第 62 条](62-fixture-fills-fallback-turns-code-dead.md)
  （夹具把「可能不给」的字段补全，兜底分支成了死代码）是同一族，方向相反：那条是
  **字段缺席**导致分支不执行，这条是**字段在场但取值太平常**导致分支不执行。
- **「同理」是最省力的一句，也是最容易假的一句。** 说「42 这样，0 同理」的人不用跑任何东西；
  验它的人要注一个变异、跑一遍、再看有没有红。成本差三个数量级，所以这句话很少被验。
- 覆盖率不会报警：那个分支执行过（`writeNativeBlock` 每一块都经过），只是没有一条用例
  **走 0 那条路径到达它**。

## 判断

> 「用例 A 证明了性质 P」这句话，先答一个问：**A 喂进去的输入，是 P 会出错的那个输入吗？**
> 不是的话，A 只证明了 P 在一个 P 不会出错的输入上成立——那是同义反复。

可以机械执行的动作：

> **把你要防的那个错读直接注进实现，然后整包跑一遍。全绿就是没有用例钉住它。**
> 别只跑 `-run` 里那几条——pattern 可能根本匹配不到你以为在跑的那条用例（同理，
> `-run 'X'` 报 `ok` 时也要先 `-list` 看一眼它匹配到了什么）。

## 解决

1. **给「特殊取值」各留一条夹具**，不是只给「一个正常样本」。0、空串、负数、上限值
   这些取值各自走的分支，要各自有输入。判据是「实现的哪条分支只有这个取值才走得到」。
2. **变异验一遍再说话**。要说「这条性质被钉住了」，就把对应的错读注进去、整包跑红，
   报出**红的用例名、失败的断言、`文件:行号`**。说不出来就还是「以为钉住了」。
3. **断言的输出要能读出「是键丢了还是值变了」**。逐字节比对失败时那句 `got/want`
   两个长串，读的人得自己找差异；补一条 `strings.Contains(body, "\"input_tokens\":0")`
   之类的具体断言，失败时那句话直接点出病因。

## 预防

- 写「A 是 P 的反证」之前，先列出 A 的输入与 P 的出错输入，**两边取值一样才说反证**。
- 评审时对「同理」「一样」「照此类推」这几个词敏感——它们标记着一处没有跑过的推断。
  问一句：「0 那条用例在哪？」
- 与[第 43 条](43-equivalence-claim-needs-distinguishing-input.md) 同族：那条讲
  「想不出用例」不等于「没有输入能区分」，这条讲「有一个用例」不等于「可区分的输入被用到」。

## 关联

- 第 62 条（夹具补齐兜底字段，被测分支成死代码）：同族，本条是「字段在场但取值不特殊」。
- 第 43 条（等价的判据是没有输入能区分）：本条是它在夹具数量上的形态。
- 第 58 条（绿得没有信息）：同族，那条讲期望值与实现同构，本条讲输入覆盖不到出错点。
- 第 16 条（跳过与通过在输出里长得一样）：`-run` 的 pattern 匹配不到用例，也是这个形状。
