# 22 · 有实现、有测试、没有门

**编号** 22 · **日期** 2026-10-17 · **摘要**：「先写库、后接线」的接缝上没有任何一步会失败，所以要把它做成一道门。

**现象**

几轮下来反复出现的同一种缺陷，形状完全一样：

| 缺口 | 现场表现 |
|---|---|
| 渠道的写入路径（#154） | 表在、代码在、测试在，生产里**没有写入方** |
| 配额与健康的两张表（#135） | 读侧齐备且被测，`ConsecutiveFailures` 恒为 0，摘除保护从不触发 |
| `snapshot_access_log`（#168） | 表建了，全仓 Go 代码**一次都没出现过** |
| 日历整条链（#182） | `internal/calendar` **整包不可达**，连内存实现都没被生产代码用过 |

从两个 main 包出发跑 `deadcode`，不可达符号数是这么走的：
**92 → 84 → 106 → 92**，门禁落地时是 **81**（接线掉了一批，白名单跟着收窄）。
**关门的速度赶不上开门的速度**——所以这一条最后不是靠「多扫几遍」解决的，
是靠把「多出来的」变成一次失败。

**原因**

「先写库、后接线」在这个仓库里是**刻意的顺序，而且是对的**——库构件应该先有、先被测，
否则接线的人要一边写业务一边造积木。

问题是这个顺序有一个**没人盯的接缝**：库写完了、测绿了、合并了，
而「谁来调它」这件事**没有任何一步会失败**。

`go build` 不报错，`go vet` 不报错，测试全绿，覆盖率还涨了。
于是这个接缝在 CI 里完全不可见，只在有人真的去用那个功能时暴露——
而那时它可能已经躺了几周，而且**看代码的人会以为它已经在生效**。

这和[第 16 条](16-silent-check-failure.md)是同一个家族：**「没跑成」与「跑成了」长得一样。**
这里的具体形态是——**「有门」与「没门」在 CI 里长得一样。**

**解决**

1. **把 `deadcode` 做成一道门**：`scripts/check-deadcode.sh` 从 `cmd/` 下的
   main 包（自动发现）出发跑 `deadcode`，与签入仓库的
   `scripts/deadcode-allowlist.txt` 比对，**新出现的不可达符号直接失败**。
   白名单里的存量各自有 issue 号，允许留着，但必须可见、可追踪；
   条目数有上限，只许减不许增。它挡的是**可达的包内部悄悄多了个没人调的函数**。
2. **再补一道包级的门**（`scripts/check-unimported.sh`）：`deadcode` 只分析
   从入口可达的包，一个全仓库没人 import 的包**整包不在清单里**
   （`internal/plugin` 就是），而「清单里没有」与「都可达」在输出上分不出来。
   所以第一道门有一个它自己挡不住的盲区，而那恰恰是「没有门」最严重的一种：
   别的包是包内多了一个没人调的符号，它是**整包没人接**。
   第二道门把「仓库自己的包」与「从入口可达的包」两个集合相减，
   差集就是整包没人 import 的那些，同样走白名单
   （`scripts/unimported-allowlist.txt`）。
   **两道门的分工是「包内的符号」与「包本身有没有接上」，缺一道就漏一半。**
3. **每一轮收尾固定复扫一次**，尤其在合并了「入口类」PR 之后——
   那时应该有一批符号从表里消失。**如果没消失，说明入口没真的接上。**
4. **报告里区分「我实现了」与「我接上了」。** 一句「X 已实现，有测试」
   不等于「X 在生产里会被调用」。这一轮做不到接线时**明说做不到**，
   别让「实现完了」这句话把接缝盖过去。

**预防**

- **写完一个库构件，顺手问一句：谁调它？** 答不上来就把它写进报告的
  「没把握 / 留给主控」一节，而不是等 `deadcode` 扫出来。
- **「测过了」不是「接上了」的证据。** 测试自己就能构造调用方，
  所以一个只有测试在调的符号，在覆盖率上和一个真的在用的符号**一模一样**。
- 反过来也要小心：**不要为了消灭不可达符号而硬接一条线。**
  `internal/money` 那类库构件进白名单是正常的——接一条假的调用方比留着它更坏。
- **「包内有没有门」与「包本身有没有门」是两个问题，一个判据答不了两个。**
  前者的工具（`deadcode`）从入口出发，于是它对后者**天然是瞎的**——
  而瞎的方式是「什么都不报」，与「全都接上了」同形。给一个检查工具补盲区时，
  先问它**看的范围是怎么定的**：范围之外的东西，它不是判成通过，是根本没看。
