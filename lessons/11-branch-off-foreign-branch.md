# 11 · 在别人的分支上开新分支，把两个改动并进了一个 PR

**编号** 11 · **日期** 2026-10-16 · **摘要**：在别人的分支上就地开新分支，会把那条分支的未合并提交一起带进自己的 PR。

**现象**

一个标题为「放行代码里的字段访问」的 PR，diff 里却包含另一个功能 PR 的全部改动。
squash 合并之后，那批文件跟着这个 PR 的提交一起进了 main，
提交信息的前半段是别人的描述，后半段才是自己的。

**原因**

为了在本地复现 CI 的失败，切到了另一条未合并的分支上。复现完**就地**开了新分支
修脚本——新分支的父提交是那条分支的 HEAD，而不是 main。

于是这个 PR 天然包含另一个 PR 的全部提交。只要那一个还没合并，
它的内容就会跟着一起被带进去。

**解决**

这次的结果恰好是对的（那批文件确实该进 main），但**过程不对**：
PR 的标题与 diff 不符，回溯时无法从这个 PR 的说明看出它带进了什么。
关掉被吞掉的那个 PR 并写明原因，记录本条。

**预防**

- 复现 CI 失败这类需要切到别人分支的操作，**切之前先记下当前分支，
  复现完立刻切回 main 再开新分支**。
- 开分支后立刻看一眼 `git log --oneline main..HEAD`：不止一条，
  说明这个分支不是从 main 干净地切出来的。
- 需要引用别人分支里的文件时用 `git show <ref>:<path>`，不要 checkout。
