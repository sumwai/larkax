# 65 · 位置找对了、名字说得出、句子就在那儿——而主语不是我以为的那个

**编号** 65 · **日期** 2026-10-28 · **摘要**：引一段注释当依据之前要问两句，
它们各挡一类错：**「这是注释还是代码」**与**「这句话的主语是谁」**。
两句都答对，仍然可能读反——因为注释常在一段里写两件事，
而其中一件的**代价说明**看起来像另一件的**行为契约**。
[第 63 条](63-difference-is-not-evidence.md)管「找不到」，本条管「找到了、读反了」。

## 现象

同一轮工作里，同一个人的三次引用错误，前两条是第 63 条那种（位置找错），
第三条不是：

| 轮次 | 引了什么 | 错在哪 |
|---|---|---|
| 一 | `gateway.go` 里 `checkOutputCap` 的那段注释 | **位置对、函数名说得出、句子就在那儿，语义读反** |
| 二 | `baseRequest()` | 名字说得出，但它答不了「它设没设那个字段」 |
| 三 | `anthropicadapter/dto.go` 的 `claudeMediaMessage.Thinking` | 同名不同物：**内容块里的思考正文** ≠ **请求顶层的 thinking 参数** |

第三条是「名字像」——同一条规矩能防住。**第一条防不住。**

那一行确实写着：

> 代价要说清楚：调用方在上限之内、而别名覆盖把它抬到上限之上时，这次请求
> **不会**在这里被拒，预留仍按覆盖之后那个数冻（见 `outputBound`）。

**整段是 `//` 注释**，讲的是 `checkOutputCap` 为什么不按覆盖后的数判——
它说的是「**预留**按覆盖值冻，而请求不会被拒」。读的人却取到了
「**发出去的那份报文**用调用方原值」这个结论。

**位置对、名字对、原文引得出，结论还是反的。** 因为那段注释在一个函数里同时说了两件事：
一件是「这里放行」，另一件是「别处按这个数算钱」。**把后者的主语换掉，前半句仍然通顺。**

## 原因

三层，一层比一层容易漏：

1. **注释不是契约。** 代码改了，注释不跟着改。它记录的是写代码的人**当时**认为的性质。
2. **注释常在一段里写两件事，而两件事的主语不同。** 「这里不拒」的主语是这个分支；
   「预留按覆盖值」的主语是另一个函数。两个主语在中文里常常都被省略。
3. **「代价」与「行为」在句式上同形。** 「X 会怎样，代价是 Y」与「X 会怎样，因为 Y」
   读起来差不多，而前者在说别处、后者在说这里。

第 63 条的五种形态都是「照着坐标去找，找不到或找到别的东西」。
本条是**找到了，而且找到了正确的那一段**——然后在同一段里认错了主语。

## 判断

引一段注释之前，两句必答：

> **① 这是注释还是代码？** 注释只当线索，不当判据——判据要落在一行会执行的代码上。
>
> **② 这句话的主语是谁？** 它说的是**谁的什么性质**：这个分支的行为，
> 还是另一个函数的代价；这次请求的报文，还是这次请求的预留？

答不出②，就把那段注释里的**每一个名词**逐个对回代码：谁在赋值、谁在读它。
对不上的那一个，就是主语被换掉的地方。

再给一条可机械执行的：

> **要断言 A 的行为，去找给 A 赋值或决定 A 的那行代码，不要去找描述它的注释。**
> 注释可以用来**找线索**（它告诉你去哪个函数看），不能用来**下结论**。

## 解决

那次的具体修法：不引注释，改引三跳代码，每一跳都是一行会执行的语句——

```
attempt, aliasErr := r.upstreamRequest(ctx, req, c)   // route.go 里选路的那一段
if err := overrides.Apply(&attempt, override); err != nil {
req.MaxTokens = vals.maxTokens                        // overrides.go 的 Apply 里
resp, err := exec.Chat(ctx, c.Channel, attempt)       // 交出去的就是 attempt
```

**四行合起来才排除了「报文用原值」这个可能**：覆盖写在 `attempt` 上，
而交给适配器的是同一个 `attempt`。原来那一句注释，
单看它写着「预留按覆盖值冻」，正好支持了那个错结论。

（**这四行有意不写行号**：它们分属两个文件、跨两个包，行号在分支之间会漂，
而这里要读者认的是「覆盖写在哪一份上」这件事，不是它此刻在第几行。）

## 预防

- **注释与代码指向不同的位置时，以代码为准，并顺手看看注释是不是该改。**
  本仓已有两处这种漂移被记下来（一个存储层的重算口径、一个金额函数的调用方说明）。
- **写「某某说 X」时，把主语写全**：「`checkOutputCap` 的注释说的是**预留**按覆盖值冻」。
  写全主语这件事本身就能发现读反——写不出来的那一半，就是没读懂的。
- **同一段注释里出现两个不同的名词时，逐个问「谁在写它」。** 一个函数里说两个函数的事
  是常态，而中文省略主语让这件事读不出来。
- 第三方依赖里的注释同此理：那里的注释与那里的版本绑定，与本仓的行为无关。
