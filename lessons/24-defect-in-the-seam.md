# 24 · 两处各自有测试，缺陷长在两处之间的缝里

**编号** 24 · **日期** 2026-10-17 · **摘要**：两处各自有用例，边界值却都没落在「两处同时生效」的那个交点上。

**现象**

Anthropic 口径的用量换算有两处会「把缓存补回输入」：
`relay.fromClaudeResponse` 在调用之后自己加一次，
`relay.UsageFromRelaykit` 内部在 `prompt == 0` 时也加一次。
`input_tokens != 0` 时第二处不触发，两处相加正好是想要的结果；
**`input_tokens == 0`（整段 prompt 全命中缓存）时两处都触发，缓存被算两遍**：

```
输入：input_tokens=0, cache_read=30, cache_write=10
期望 prompt = 40，实测 prompt = 80
```

两处**各自都有用例**：

- 喂 `input_tokens = 100` 的那组走的是「第二个分支不触发」那条路；
- `TestUsageCacheOnlyImpliesPrompt` 直接调 `UsageFromRelaykit`，
  绕过了调用方那次加法。

所以两条用例都在回避那个缝，各自的覆盖率都好看。这是[第 22 条](22-implemented-tested-ungated.md)（有实现、有测试、
没有门）的一个变体：那里缺的是**门**，这里缺的是**交点**。

**预防**

- 一个判据有**两个落点**时（同一件事在两处各做一次、或调用方与被调用方各做一次），
  用例的边界值要落在「两处同时生效」的那个交点上。写之前先问：
  **这两处同时触发时结果是什么？** 答不上来就说明这个组合没被测过。
- 反过来，看到「同一件事在这里也做了一次」的注释时，先确认它**是否幂等**：
  不幂等的两处叠加就是这类缺陷，而每一处的单测都会通过。
- 合并前把两处的判据并排读一遍，比读两遍各自的用例有用。
