# 7 · 红线扫描按整行过滤，会让真密钥搭占位符的便车溜过去

**编号** 7 · **日期** 2026-10-16 · **摘要**：过滤粒度是整行时，行内任意一个占位词就能把同一行上的真密钥一起放行。

**现象**

[第 2 条](02-grep-combined-flags-silent-miss.md)修好之后，脚本的漏报换了一副面孔。拿一份植入真凭证的样本试，四行里只报出两行：

```
<前缀型密钥>        → 报
<无引号短密钥>      → 报
<连字符写法口令>    → 不报
<长密钥，右侧含斜杠> → 不报
```

**原因**

三处各自独立的口子：

1. **过滤粒度是整行。** 脚本用 `grep -viE "$ALLOW"` 丢掉「含占位词」的行。
   只要同一行别处出现 `example` 或 `占位`，该行上的真密钥就被一并放过。
   而各家文档里的样例密钥恰恰带着 `EXAMPLE` 字样——正是把 `EXAMPLE`
   写进白名单的人最想拦住的那类字符串，却因为白名单本身被放过了。
2. **右侧只认字母数字。** 模式尾巴是 `[A-Za-z0-9]{12,}`，
   而真实口令大量写成 `correct-horse-battery-staple` 或 `correct_horse_battery`。
3. **`-o` 缺失。** 不取命中片段就只能按行判断，观察不到「这个片段本身是不是占位」。

**解决**

1. `grep` 加 `-o`，只取命中**片段**。
2. 分两类模式，过滤粒度不同：
   - **形态类**（密钥前缀、私钥头、私有主机）：片段整体就是敏感内容，按整个片段过 `ALLOW`。
   - **赋值类**（`key = value`）：只把 `=` 右侧的**值**拿去过滤。
     键名里带 `example` 不该放过同一个片段里的真值，所以这两类必须分开。
3. 右侧字符集放宽到 `[A-Za-z0-9_-]`，覆盖连字符与下划线写法的口令。
4. `-o` 的片段会被截断（`"${LARKAX_API_KEY}"` 取到 `"${LARKAX_API_KEY`），
   所以环境变量引用的放行模式写成 `\$\{?[A-Za-z0-9_]*\}?`，不要求闭合花括号。

同时补了 `scripts/check-redlines.test.sh`：30 个用例，命中与放行两侧都有。
[第 2 条](02-grep-combined-flags-silent-miss.md)的预防里写过「检查脚本必须带一份会触发命中的样本」，但当时只留了个手工样本，
没有固化成可重复执行的用例，于是同一个脚本又漏了一次。

**预防**

- 白名单过滤的粒度要跟着**判断单元**走：判断的是片段就别按行过滤。
- 样例值（`EXAMPLE`、`AKIA...EXAMPLE`）不能进白名单——那正是要抓的东西。
  白名单只放行**结构性**的占位形态：`<API_KEY>`、`${VAR}`、`placeholder`。
- 「带样本自测」要落成可执行文件并进 CI，不能只写在文档里靠人记得。
