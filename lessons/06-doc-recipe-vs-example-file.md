# 6 · 文档推荐的做法配着自己的示例文件必然报错

**编号** 6 · **日期** 2026-10-16 · **摘要**：示例文件按「给人看的模板」写、文档里的命令按「可执行的脚本」用，两者凑在一起必然报错。

**现象**

`docs/development.md` 推荐用 `set -a && . ./.env && set +a` 加载配置，
而仓库里的 `.env.example` 里写着 `LARKAX_DB_DSN=postgres://user:<DB_PASSWORD>@localhost:5432/larkax?sslmode=disable`。
照着做必然报语法错——`<DB_PASSWORD>` 被 shell 当成输入重定向。行内的 `# 注释` 也会被当成值的一部分。

**原因**

`.env.example` 是按「给人看的模板」写的，`.env` 是按「可被 shell 读取的脚本」用的，
两者格式不同，但文件名相似、位置相邻，没人会想到它们不兼容。写文档和写示例的是同一个人，
各自都自洽，凑在一起就坏了。

**解决**

把 `.env.example` 改成 shell 可 source 的形态：每个值加引号、注释单独占行，
并在文件开头写明「本文件可以直接被 shell 读取」。

**预防**

- 文档里的命令，要连着仓库里的示例文件一起跑一遍，而不是只看命令本身对不对。
- 面向使用者的文档必须由**不看文档背景的人**按字面执行一遍。这条正是「假装首次使用者」
  测试能抓到、而自查抓不到的问题。
