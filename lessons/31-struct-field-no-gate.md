# 31 · 结构体字段的死活，三道门都照不到——而「有没有读者」不是判据

**编号** 31 · **日期** 2026-10-17 · **摘要**：三道门只覆盖函数、方法、包；判据不是「有没有读者」，而是「它是不是别的字段的函数」。

**现象**

`deadcode`、`check-unimported.sh`、`check-deadmethods.sh` 三道门覆盖的是**函数、
方法、包**。**结构体字段**这一类它们一道都照不到：删一个没人读的字段，三道门
全绿；留一个没人读的字段，三道门也全绿。所以「这个字段还有没有用」只能靠人读。

连着三处都长在这一类上：`Settlement.Delta`（#313）、`Charge.Breakdown`（#319）、
`billing.Rule`（#282，整个导出类型）。

**「有没有生产读者」是错的判据**

第一版判据是「有没有生产读者」，它会把该留的判成该删：
`Settlement.Reserved` 同样**没有生产读者**，但它是**独立入参**（预留的上界），
不是别的字段算出来的。删了它，那条信息就没了，而不是「少了一份表示」。

**对的判据是两条，两条都成立才收**

1. **它是不是别的字段的函数？**
   `Delta = Actual - Reserved`、`Breakdown = settlement.Breakdown`——构造时直接从
   同一结构体的另一个字段（或从它算出来）赋值，是**同一份信息的第二份表示**。
2. **注释里描述的那条分支走不走得到？**
   `Delta` 的注释说「正数表示还要再扣」，而 `Actual = min(Total, Reserved)` 让它
   永远 ≤ 0——那条分支从来不会执行，注释在描述一条不存在的路。

**「删了测试还绿」不够，要「把值改成错的、测试照样绿」**

#319 给出的证据比前者强一档：把字段加回去、并**故意把值写成错的**（零值而不是
`settlement.Breakdown`），全部用例照样绿。这说明它此前不是「被测试钉住」，
只是「被测试**路过**」——删它不会让任何既有保证变弱。

判据与证据形式是配套的：只测「删掉之后还绿」，测的是**没有别的测试依赖它**；
把值改错还绿，测的才是**它自己的值有没有被钉住**。这两件事在覆盖率上长得一样
（[第 22 条](22-implemented-tested-ungated.md)、[第 23 条](23-untested-guard.md)同一族）。
