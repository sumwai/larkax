# 5 · goose 的 down-to/up-to 会停在目标版本的相邻位置

**编号** 5 · **日期** 2026-10-16 · **摘要**：goose 的 `down-to` 停在目标版本的相邻位置，差一位不报错，只把状态静默留在错的地方。

**现象**

迁移工具封装了 `migrate down-to <版本>`，转调 goose 的同名功能。
数据库在 v2 时执行 `migrate down-to 0`，实际只回滚到 v1，需要再执行一次才到 v0。

**原因**

goose 的 `down-to` / `up-to` 语义不是「推进到目标版本为止」，而是别的（停在相邻位置）。
差一位比不支持更危险——使用者会以为已经回滚干净了，然后在一个半旧的库上继续工作。

**解决**

不再转调，自己按版本号循环推进：

```go
for {
    current, _ := goose.GetDBVersionContext(ctx, db)
    if current <= target { return nil }        // 回滚方向
    goose.DownContext(ctx, db, ".")
}
```

行为变成「版本号到目标为止」，与直觉一致，也好测。

**预防**

包装第三方命令时，先手工验证边界行为再信任它的名字。
「差一位」「差一个」「少一次」这类错误不会报错，只会静默地把状态留在错误的位置。
