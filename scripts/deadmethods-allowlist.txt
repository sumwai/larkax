# check-deadmethods.sh 的白名单：允许暂时没有调用点的导出方法。
#
# 格式，一条一行，四栏用 | 隔开（理由里不能出现 |）：
#
#   <文件路径> | <符号名> | <类型> | <理由>
#
# 以 `#` 开头的行是注释（行首的空格不影响，`   # …` 同样算），它们**不是条目**：
# 既不参与四栏的格式校验，也不计进条数。注释可以写在条目区里——用来说明那个位置
# 上原本有什么，下面 `internal/billing/billing.go` 之前那一段就是一例。
#
# 路径与符号名取扫描结果里的那两栏（`internal/money/money.go|Amount.Units`
# 取 `internal/money/money.go` 与 `Amount.Units`），**不带行号**——行号会随任何
# 一次编辑漂移，那样每改一行代码白名单就得全量重写，第二次就没人维护了。
#
# 类型两档，与 scripts/deadcode-allowlist.txt、scripts/unimported-allowlist.txt
# 同一套：
#
#   lib  库构件 / 测试夹具。先有库、后接线是这个仓库刻意的顺序，库构件本来就该
#        先有、先被测；测试夹具更是永远不会被生产代码调。
#   gap  被追踪的缺口。理由里**必须**带一个 issue 号（`#123`），
#        否则 check-deadmethods.sh 会拒绝这份白名单。
#
# 这一档的用处是让 review 能问出「这一条为什么还在」：lib 的答案是「它是积木 /
# 它是夹具」，gap 的答案是「有一个 issue 在跟」。
#
# **lib 那几条的理由要写清「目前只有测试在调」**——「有实现、有测试、没有调用方」
# 的方法，看代码的人会以为它已经生效。理由栏说不清的事，对应方法的注释里要补一句。
#
# 本文件按 <路径> 再按 <符号名> 排序，与扫描结果里的顺序无关——
# 比对按集合做，加一条或删一条只动一行。
#
# 这份清单产出时的条件（换任何一个，条数都不可比）：
#
#   命令      scripts/check-deadmethods.sh
#             （扫描起点由 cmd/ 自动发现，当前是 ./cmd/larkax 与 ./cmd/larkaxctl）
#   工具      go（版本随 go.mod；判据是脚本里嵌的那份 AST 扫描器）
#   条数      见脚本里的 MAX_ENTRIES_DEFAULT（**本文件不重复这个数**——
#             抄一份就多一处会漂的地方，而脚本每次运行都会打印实际条数）
#
# # 这份清单与 scripts/deadcode-allowlist.txt 的关系
#
# **两份清单不共享条目，有重叠是正常的。** 两道门的判据不同（一道看调用图，
# 一道看语法），同一个符号可能在两边各记一条，也可能只在一处出现：
#
#   MemorySource.AddDay          两边都有（那边：不是 runtime type；这边：没人调）
#   catalog.Admin.Update         只在 deadcode 那边有——`.Update(` 在别处出现过，
#                                这道门的判据按方法名做，于是它看不见（见脚本开头
#                                「同名方法互相掩护」那一段）
#   money.Amount.Units           只在这边有——它在 RTA 的盲区里，deadcode 报不出来
#
# 不共享是有意的：共享之后「改一处要动两处」会变成三处，而两道门的判据将来
# 还可能各自调整。
#
# # 一条 gap 的两种下场
#
# **gap 挂的 issue 一旦关闭，条目就成了死链。** 一条 gap 有两种下场，得分开看：
# 缺口在那条 issue 里兑现了，就把条目删掉（哪次删了哪几条，记在上面那几段
# 「减了几条」里）；缺口没做、只是那张单子关了，就把它改挂到一条活的跟踪
# issue 上。留着不换的话，后来的人照编号点过去只看到一张已经关掉的单子，
# 而条目还在清单里，看上去像有人在盯，其实没有。
#
# **删掉一条陈旧条目时，提交信息里要写明是哪一种。** 陈旧条目只提示、不算失败
#（见脚本开头「白名单」那一节），所以两种删法在记录里长得一样：一种是上面说的
# 「缺口兑现了」，另一种是**被同名掩护掉**——这道门按方法名数调用点（见脚本开头
# 「同名方法互相掩护」那一段），别处冒出一个同名调用点就能把它从扫描结果里划掉，
# 不需要任何人做决定。后者是**清单少了一条提醒**：缺口还在，只是不再挂门、也不
# 再挂 issue 了。本文件已经出过这么一例，见下面 `internal/billing/billing.go`
# 之前那一段。
#
