# 契约测试用的官方客户端 SDK。
#
# 版本必须**精确钉住**（`==`，不是 `>=`）。理由与 gremlins / deadcode 那两次一样：
# 不钉版本的工具，它的结论不可比。SDK 的一个大版本升级会改响应形状的解析，
# 于是「昨天绿、今天红」说明不了任何事——它既可能是我们的形状坏了，
# 也可能是 SDK 的解析器变了，而这两件事的处置完全不同。
#
# 钉的是 2026-10-09 发布的这两个版本。取法是「**钉版本当天已发布满 7 天**的
# 最新稳定版」（钉版本日期 2026-10-17）：
#
#   - 契约测试验的是「SDK 的解析器认不认我们的响应形状」，所以要的是一个
#     被广泛用过、行为稳定的解析器，而不是当天刚发出来的那一版。
#   - openai 的发布节奏是每天数个版本（2026-10-09 之后一周内又发了
#     3.29 ~ 3.33 五版），anthropic 约每周一版。取「满 7 天」让两边落在
#     同一天，于是这条规则本身一句话能说清，不必为每个包各编一个理由。
#   - 更早的版本也行，但离得太远就验不到「现在的客户端还认不认」。
#
# 查法（PyPI 的 JSON API，releases 里每条带 upload_time_iso_8601）：
#   curl -s https://pypi.org/pypi/openai/json | python3 -c \
#     "import json,sys; r=json.load(sys.stdin)['releases']; \
#      print(sorted((v[0]['upload_time_iso_8601'], k) for k,v in r.items() if v)[-12:])"
#
# 升级这两个版本时，要连着读一遍契约测试的结论：形状断言有没有跟着变。
openai==3.28.0
